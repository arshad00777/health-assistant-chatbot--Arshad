# Wellpoint — Health Assistant Chatbot (Prototype)

A working RAG + LangGraph + LLM health-information chatbot, built as a single
Next.js app so it deploys straight to Vercel. This implements the
architecture from your diagram, simplified where noted so it runs with zero
external services besides an OpenAI API key.

## What's actually implemented vs. simplified

| Diagram box | In this prototype |
|---|---|
| React.js frontend, chat UI, sources | ✅ `app/page.tsx` — real chat UI, shows sources, saves history to `localStorage` |
| Admin panel | ✅ `app/admin/page.tsx` — view KB stats, add new FAQs |
| Node.js + Express backend API | ✅ Next.js Route Handlers (`app/api/*`) instead of a separate Express server — same REST contract, one deployable app |
| Document ingestion + chunking | ✅ `scripts/ingest.mjs` — reads `data/kb/*.md`, chunks by section |
| Vector database (Pinecone/Chroma/FAISS) | ⚠️ Simplified to a flat JSON file + in-memory cosine similarity (`lib/vectorstore.ts`) — real RAG, no external DB to provision. Swap-in point noted below. |
| LangGraph workflow | ✅ `lib/graph.ts` — a real `StateGraph` with `retrieve → generate` nodes, decides whether retrieved context is relevant enough to use |
| LangChain chains/tools | ⚠️ Simplified to direct OpenAI SDK calls for reliability in a prototype. Easy to swap for `@langchain/openai` chains — see "Extend" below |
| MongoDB (user profiles, chat history, analytics) | ⚠️ Not included. Chat history is per-browser (`localStorage`). See "Extend" below |
| Auth / JWT | ⚠️ Not included — this is an open prototype. See "Extend" below |

## Stack

- **Next.js 14** (App Router, TypeScript) — frontend + API in one deployable
- **OpenAI API** — `text-embedding-3-small` for embeddings, `gpt-4o-mini` for generation
- **@langchain/langgraph** — orchestrates the retrieve → generate workflow
- Plain JSON file as the vector store (no external DB required)

## 1. Run it locally

```bash
# 1. Install dependencies
npm install

# 2. Add your OpenAI API key
cp .env.example .env
# then edit .env and paste your key: OPENAI_API_KEY=sk-...

# 3. Build the knowledge base (embeds data/kb/*.md into data/vectorstore.json)
npm run ingest

# 4. Start the dev server
npm run dev
```

Open **http://localhost:3000** to chat, and **http://localhost:3000/admin**
for the admin panel.

Try asking: *"How much water should I drink a day?"* or *"What should I do
about a bad headache?"* — you'll see the answer plus which knowledge-base
file it was grounded in.

## 2. Deploy to Vercel

1. Push this project to a GitHub repo (or use `vercel` CLI directly from this folder).
2. In Vercel: **New Project → Import** your repo.
3. Under **Environment Variables**, add:
   - `OPENAI_API_KEY` = your key
   - (optional) `EMBEDDING_MODEL`, `CHAT_MODEL` if you want to override defaults
4. Deploy.

**Important:** `data/vectorstore.json` needs to contain your embedded chunks
*before* you deploy, because Vercel's filesystem is read-only at runtime.
Run `npm run ingest` locally first, then commit `data/vectorstore.json` (or
run ingest as part of your build step) so it ships with the deployment.

If you add or edit files in `data/kb/`, re-run `npm run ingest` locally and
redeploy (or commit the updated `vectorstore.json`).

## 3. Opening it in VS Code

1. Unzip the project.
2. `code health-assistant-chatbot` (or File → Open Folder).
3. Open a terminal inside VS Code and follow the "Run it locally" steps above.
4. Recommended extensions: ESLint, Prettier — none are required to run it.

## Project structure

```
app/
  page.tsx              chat UI (client component)
  page.module.css
  admin/page.tsx         admin panel (KB stats + add FAQ)
  api/chat/route.ts       POST /api/chat -> runs the LangGraph workflow
  api/admin/kb/route.ts   GET/POST /api/admin/kb -> knowledge base management
  layout.tsx, globals.css
lib/
  graph.ts               LangGraph StateGraph: retrieve -> generate
  vectorstore.ts          JSON-backed vector store + cosine similarity search
  openai.ts               OpenAI client + embedding helper
data/
  kb/*.md                 source health documents (edit/add your own)
  vectorstore.json        generated by `npm run ingest` — do not hand-edit
scripts/
  ingest.mjs              chunks + embeds data/kb/*.md into vectorstore.json
```

## What I'd extend first

1. **Real vector database.** Swap `lib/vectorstore.ts`'s `search()` for a
   Pinecone or Chroma query call once your knowledge base grows past a few
   hundred chunks (JSON + cosine similarity is fine up to a few thousand
   chunks, but won't scale indefinitely and re-embeds everything on every
   `ingest` run).

2. **Persistent chat history + user accounts.** Add a Postgres/MongoDB
   instance (Vercel Postgres or MongoDB Atlas both work well with Vercel),
   store `{ userId, messages, sources, timestamp }`, and add basic auth
   (NextAuth.js is the fastest path) so the admin panel isn't wide open.

3. **A real LangChain agent with tools.** Right now the LLM only reads
   retrieved context. The diagram's "Tools (health calculators, APIs)" box
   is a natural next step — add a LangGraph node that lets the model call a
   BMI calculator, a drug-interaction lookup, or a symptom-checker API, and
   route to it conditionally based on the question (LangGraph's conditional
   edges are built for exactly this).

4. **Guardrails.** Add a lightweight moderation/safety check node before
   `generate` (e.g. flag self-harm language and respond with crisis
   resources instead of the normal pipeline) — important for any real
   health-facing product before it sees real users.

5. **Admin persistence.** The current "Add FAQ" form writes to a local file
   (or `/tmp` on Vercel, which doesn't persist). Once you have a database,
   point this at it and re-embed new entries automatically on save instead
   of requiring a manual `npm run ingest`.

## Safety note

This prototype includes disclaimers and steers the model toward general,
cautious information, but it is a demo — it has not been clinically
validated. Don't use it to make real medical decisions.
